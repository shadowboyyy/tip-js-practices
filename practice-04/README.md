## Отладка и клавиатура
Точки останова установлены через Chrome DevTools Protocol в handleFormSubmit после validateTaskDraft и после сохранения. Сырой draft содержит id="20", title="Изучить localStorage", priority="high". После проверки id=20 — число, ok=true. Сервис вернул ok=true и новый список из пяти задач; в JSON записаны version=1 и этот список. При повторном id="4" получены ok=false и errors.id, сервис не вызывался. При редактировании disabled-поле id отсутствует в FormData, поэтому draft.id=null, а валидатор использует editingId=4.

Снимки переменных, результата сервиса и полной строки JSON: [scenarios.json](verification/scenarios.json). Enter на edit открывает редактирование, Space на отмене возвращает форму создания. При начале редактирования фокус на task-title, после отмены на task-id; следующий Tab переходит к task-title.

## Контрольные вопросы
1. Обработчик submit охватывает и кнопку, и отправку с клавиатуры.
2. preventDefault отменяет стандартную отправку/переход; выполнение обработчика продолжается.
3. Для обычных полей FormData.get возвращает строку, при отсутствии — null; для файлов возможен File.
4. Disabled-поля не включаются в данные формы; id берётся из editingId.
5. HTML проверяет required, min, step и maxlength; модель — уникальность id, safe integer, trim и допустимый приоритет.
6. Пробелы образуют непустую строку до trim.
7. setCustomValidity("") снимает старую ошибку, reportValidity показывает текущее нарушение.
8. Чистый валидатор можно тестировать отдельно и использовать с другим представлением.
9. editingId=null означает создание; число означает редактирование найденной задачи.
10. Изменение названия и приоритета не должно менять независимый статус задачи.
11. localStorage хранит строки.
12. Отсутствие записи — нормальное начальное состояние; повреждение — повод для предупреждения.
13. У JSON могут быть неверные типы, поля, значения и повторяющиеся id.
14. version позволяет обнаружить несовместимую схему.
15. Частично восстановленный список мог бы скрыть потерю данных; контракт требует целостного набора.
16. Явный storage позволяет подменить хранение и воспроизвести исключения в тесте.
17. При setItem возвращается ok=false; интерфейс сохраняет изменение в памяти и показывает предупреждение.
18. Отрисовка не означает изменение модели; запись при каждом фильтре была бы лишней.
19. Фильтр и режим редактирования — временное состояние интерфейса по контракту работы.
20. Разные ключи сохраняют независимость demo и variant.
21. Namespace проверок защищает рабочие данные от тестового сброса.
22. removeItem удаляет один ключ; clear удалил бы данные всего origin.
23. Порт входит в origin, к которому привязан localStorage.
24. Клавиатура, фокус, сообщения конкретного браузера и индивидуальный сценарий дополнительно проверяются в интерфейсе.
