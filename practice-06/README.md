## Цель и результат

Клиент ПР5 расширен изменяющими запросами и подключён к браузерному интерфейсу. Задачи и категории поступают с сервера; создание, редактирование, смена статуса, удаление и сброс подтверждаются HTTP API.

## Реализация

### HTTP-клиент

`api-client.js` сохраняет решение ПР5 и поддерживает GET, POST, PATCH, DELETE. Метод переводится в верхний регистр; неподдерживаемый метод и тело у GET отклоняются до fetch. Accept передаётся всегда, JSON.stringify и Content-Type — только при наличии body. После fetch проверяются Response и response.ok, затем 204, Content-Type и JSON. 204 возвращает null. ApiError сохраняет kind, status, code, details, url и cause; тайм-аут 3000 мс объединён с внешним сигналом.

### Предметный API и форма

`task-api.js` реализует getTasks, getTaskById, getCategories, loadInitialData, createTask, updateTask, setTaskCompleted, deleteTask и resetDemoData. Методы получают необязательный signal. Коллекции проверяются на поля модели, уникальные id и соответствие meta.total. Каждая полученная задача проходит isTask; категории — isCategory; delete требует null, reset — reset=true и целое total.

POST отправляет только title, priority и categoryId; id и начальный completed назначает сервер. PATCH редактирования не включает completed. validateTaskDraft возвращает valid, value и errors; название нормализуется trim, приоритет проверяется по набору, categoryId преобразуется в число и сверяется с загруженными категориями. При ошибке формы API не вызывается.

`task-view.js` создаёт li.task-card с data-task-id, названием, статусом, приоритетом, категорией и тремя действиями. Пользовательские строки передаются в textContent. replaceChildren не накапливает карточки.

### Состояния и изменения

Контроллер получает api и view аргументами, не обращается к document. Состояния:

```text
start / filters / refresh → loading → ready (есть задачи)
                                 → empty (успешно, задач нет)
                                 → error (ошибка загрузки)
error → повтор → loading
```

Первая загрузка параллельно получает задачи и категории. Если она не удалась, refresh снова выполняет loadInitialData. После успешной мутации контроллер очищает форму при необходимости и повторяет GET с актуальными фильтрами. На время операции кнопки заблокированы; finally снимает блокировку. Ошибка мутации показывается без потери формы и уже загруженных данных.

### Защита от устаревшего ответа

Перед загрузкой предыдущий AbortController отменяется, номер загрузки увеличивается. После await результат применяется только при совпадении номера. Даже подмена API, не соблюдающая signal, не сможет заменить новый список старым. Ошибки aborted пользователю не показываются. destroy отменяет загрузку и запрещает дальнейшую отрисовку.

## Контрольные вопросы
1. fetch считает полученный 404/500 HTTP-ответом; клиент сам проверяет response.ok.
2. Сначала response.ok и ветка HTTP-ошибки; для успеха — 204, Content-Type, затем JSON.
3. POST создаёт задачу без клиентского id/completed, PATCH меняет переданные поля существующей.
4. 201 означает создание; Location указывает адрес нового ресурса.
5. У 204 нет JSON-тела, поэтому json() завершился бы ошибкой.
6. Preflight возникает для междоменных запросов с несвободными методами/заголовками, например PATCH или JSON Content-Type. no-cors ограничивает доступ и не делает такой API доступным.
7. empty — успешная загрузка пустого списка, error — отсутствие успешного результата.
8. В этой работе источником истины служит HTTP API, а не браузерная копия.
9. Повторный GET учитывает серверные правила, новый id и действующие фильтры.
10. Ответ первого запроса может прийти после ответа второго и затереть актуальный список.
11. Отмена может опоздать, а подмена API может игнорировать signal; нужна проверка номера загрузки.
12. Отмена — ожидаемое следствие нового пользовательского действия.
13. Клиент проверяет удобство ввода и ответы; сервер обязан проверять id, JSON, поля, типы и правила модели независимо от клиента.
14. view позволяет тестировать контроллер без DOM и отделяет сценарии от разметки.
15. textContent выводит данные как текст и не исполняет присланную разметку.
